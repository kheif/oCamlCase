How to Learn OCaml on This Site

Before the first concept: how this site is organized, where to run code, and the study loop that makes the material stick.

Two ways through the material

The same pages can be read in two orders. Pick the one that matches you on the home page:

  • Guided Path: a phased sequence for learning from scratch. Each phase builds only on earlier phases, so nothing arrives before its prerequisites. If OCaml or functional programming is new to you, use this.
  • Reference: a flat topic list for readers who already know the ideas and want to jump straight to a page. The Cheat Sheet is the fastest entry point in this mode.

The sidebar, the numbering on each page, and the Next links at the bottom of every concept all follow whichever mode you picked. Switching is instant and keeps your place.

Where to run code

Every code block has a copy button. Paste the code into the Playground, which runs OCaml directly in your browser. Nothing to install.

Use the Playground constantly, not just when a page tells you to. Reading OCaml and writing OCaml are different skills; only the second one makes the first one easy.

The study loop

On every example: read the code, predict what it evaluates to, run it in the Playground, then modify it until it breaks or surprises you. Repeat. A prediction that turns out wrong teaches more than ten pages that read smoothly.

Error messages are guides, not enemies

OCaml's compiler rejects a lot of programs that other languages happily run and then crash. That is the deal: the compiler does the crashing up front, with a message, before your program ever runs.

So when you see an error, do not retreat to the previous working version. Read the message. It almost always names the exact expression, the type it has, and the type it was expected to have. Learning to decode these messages is a core OCaml skill, and it has its own page: Reading Compiler Errors.

How the pieces fit

  • Concepts are the main path: each page is one idea, with examples and (often) an animated demo.
  • Mini exercises are short drag-and-drop drills linked from concept pages. Do them right after the page they belong to.
  • Exercises are larger coding challenges that combine several concepts. Attempt them at phase boundaries.
  • Interactive Labs (TreeLab, Static Semantics, the Interpreter series) go deeper into how the language itself works. They reward a second visit after you finish the path.

One sentence to keep

Writing OCaml is mostly two activities: designing the shape of your data, and writing total functions over that shape. Every phase of the guided path serves one of those two activities. When a page feels abstract, ask which of the two it is sharpening.
