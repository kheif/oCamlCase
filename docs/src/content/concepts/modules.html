Modules and Signatures

Modules group related types and functions into named units; signatures describe what a module exposes. Together they are OCaml's main tool for organizing programs and hiding implementation details.

You have been using modules all along

List.map, Float.sqrt, Option.bind: the capitalized name before the dot is a module, and the dot reaches inside it. Every .ml file is itself a module, named after the file: code in utils.ml is reachable from other files as Utils.whatever.

Defining a module

module ... = struct ... end creates a module by hand. Anything defined between struct and end becomes a member: types, values, functions, even other modules.

Outside the module, members are reached with the dot, or brought into scope with open. Prefer the dot or a local let open ... in; a file-wide open makes it hard to see where names come from.

counter.ml 
module Counter = struct
  type t = int
  let zero : t = 0
  let incr (c : t) : t = c + 1
  let value (c : t) : int = c
end

let c = Counter.incr (Counter.incr Counter.zero)
(* Counter.value c = 2 *)

Signatures: the public face

A signature (sig ... end, or an .mli file for a file-module) lists what the outside world may see. Everything not listed is invisible.

counter_sig.ml 
module Counter : sig
  type t                    (* abstract: no "= int" *)
  val zero : t
  val incr : t -> t
  val value : t -> int
end = struct
  type t = int
  let zero = 0
  let incr c = c + 1
  let value c = c
end
Key insight

Writing type t in the signature without its definition makes the type abstract: callers can hold a Counter.t and pass it around, but they cannot do c + 1 themselves or forge one from an int. The only ways to make or change a counter are the functions the signature exports. Invariants enforced this way cannot be broken by any caller.

Files as modules: .ml and .mli

In a real project you rarely write module ... = struct at the top level. Instead each file is a module, and a sibling .mli file is its signature:

  • stack.ml defines the implementation.
  • stack.mli declares the interface; only what it lists is visible to other files.

An .mli doubles as documentation: a reader learns the whole API of a file from one short page of val declarations.

Nested access and local opens

opens.ml 
(* dot access: always unambiguous *)
let total = List.fold_left (+) 0 [1; 2; 3]

(* local open: scope limited to one expression *)
let mean xs =
  let open List in
  fold_left (+.) 0. xs /. float_of_int (length xs)

(* even shorter: M.(...) *)
let shout s = String.(uppercase_ascii (trim s))

Where this leads

Signatures also make modules interchangeable: any module matching the signature can stand in for another. Taking that idea one step further, a module can be parameterized over another module.
