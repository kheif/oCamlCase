Mutability: Refs and Arrays

OCaml is immutable by default, but it is not a pure language. Refs, arrays, and loops are there when in-place state is genuinely the right tool, and they come with sharing and equality pitfalls worth knowing.

Refs revisited

A ref is a single mutable cell, introduced briefly in Bindings. The binding to the cell never changes; the cell's contents do. You write with :=, read with !, and for integer cells incr and decr abbreviate the common cases.

The type makes mutation visible: int ref is a different type from int. You can never accidentally treat a cell as its contents, the ! is always explicit.

Key point

Assignment := returns unit, the type with the single value (). Expressions executed only for their effect have type unit, and the semicolon ; sequences them: e1; e2 runs e1 for its effect, then evaluates to e2.

refs.ml 
let counter = ref 0
(* counter : int ref *)

counter := !counter + 5
incr counter
!counter            (* 6 *)

(* := has type 'a ref -> 'a -> unit *)

Arrays

An array is a fixed-size block of mutable cells with constant-time indexed access. Where a list is built for structural recursion, an array is built for random access and in-place update.

  • Literal syntax uses [| ... |] with semicolons.
  • arr.(i) reads index i; arr.(i) <- v writes it. Both are bounds-checked and raise Invalid_argument when out of range.
  • Array.make n x builds an array of n copies of x; Array.length, Array.map, and Array.iter mirror their List counterparts.
arrays.ml 
let a = [| 10; 20; 30 |]
(* a : int array *)

a.(1)               (* 20 *)
a.(1) <- 25
a.(1)               (* 25 *)

let zeros = Array.make 4 0
(* [| 0; 0; 0; 0 |] *)

Array.length a     (* 3 *)

while and for loops

With mutable state available, OCaml's loops become useful. Both are expressions of type unit: they exist purely for their effects, which is why they only make sense together with refs or arrays.

A for loop walks a fixed integer range; a while loop runs as long as its condition reads true, so the condition must mention something mutable or it will never change.

Notice the shape of the sum below: the loop variable does the walking and a ref does the accumulating. The same computation written functionally is Array.fold_left (+) 0 a, the idiomatic version.

loops.ml 
let sum_array a =
  let total = ref 0 in
  for i = 0 to Array.length a - 1 do
    total := !total + a.(i)
  done;
  !total

let countdown n =
  let i = ref n in
  while !i > 0 do
    print_int !i; print_newline ();
    decr i
  done

Sharing and equality

Mutation introduces a question immutable code never asks: are these two values the same cell, or merely equal in content? OCaml has an operator for each.

  • = is structural equality: do the contents match?
  • == is physical equality: is this literally the same object in memory?
Pitfall

Two refs holding equal contents are = but not ==. And when two names share one cell, writing through either is visible through both. Use = for comparisons unless you specifically need to detect sharing.

sharing.ml 
let r = ref 1
let s = ref 1
let alias = r      (* alias shares r's cell *)

r = s              (* true: equal contents *)
r == s             (* false: different cells *)
r == alias         (* true: same cell *)

alias := 99
!r                 (* 99: the write is visible through r *)
Good practice

Default to immutability. Reach for refs and arrays when an algorithm genuinely calls for in-place state, tight numeric loops, memo tables, counters observed across calls, and keep the mutable part small and local so the rest of the program stays easy to reason about.
