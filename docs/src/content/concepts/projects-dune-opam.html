Projects with dune and opam

Leaving the Playground: opam installs the compiler and libraries, dune builds multi-file projects. A minimal project needs about ten lines of configuration.

The two tools

  • opam is the package manager: it installs OCaml itself, libraries, and developer tools, in isolated environments called switches.
  • dune is the build system: it compiles your files in dependency order, handles .mli interfaces, runs tests, and produces executables and libraries.
terminal 
# one-time setup
opam init
opam switch create 5.2.0       # a fresh compiler environment
opam install dune utop ocaml-lsp-server ocamlformat

A minimal project

dune reads small declarative files, each named dune, that say what lives in each directory. The layout on the right is the conventional split:

  • bin/ the executable entry point
  • lib/ the actual logic, as a library
  • test/ tests against the library

Keeping logic in lib/ rather than bin/ matters: libraries can be used by both the executable and the tests.

project layout 
hello/
├── dune-project
├── bin/
│   ├── dune
│   └── main.ml
├── lib/
│   ├── dune
│   └── greet.ml
└── test/
    ├── dune
    └── test_greet.ml
dune-project 
(lang dune 3.0)
lib/dune 
(library
 (name greet))
bin/dune 
(executable
 (name main)
 (libraries greet))
lib/greet.ml + bin/main.ml 
(* lib/greet.ml *)
let hello name = "Hello, " ^ name ^ "!"

(* bin/main.ml: file Greet.ml becomes module Greet *)
let () = print_endline (Greet.hello "world")
terminal 
dune build          # compile everything
dune exec bin/main.exe
# Hello, world!
dune test           # build and run the test directory
Key insight

Notice what is absent: no file lists, no compile flags, no dependency ordering. dune discovers the .ml files in each directory, computes the module dependency graph itself, and rebuilds only what changed. Each file is a module (see Modules and Signatures); the build system and the module system are two views of the same structure.

Using a library from opam

Two steps, always the same: install with opam, declare in the dune file.

terminal + lib/dune 
opam install yojson

; lib/dune
(library
 (name greet)
 (libraries yojson))

The day-to-day loop

  • dune build -w rebuilds on every save (watch mode); type errors appear in the terminal as you edit.
  • dune utop lib opens a REPL with your library loaded, the project-sized version of the Playground.
  • dune fmt formats the whole project (see Testing and Code Quality).

With an editor running ocaml-lsp-server you also get inferred types on hover, the fastest way to apply the type-reading habits from Reading Compiler Errors.
