Trees

Trees are recursive data structures that naturally model hierarchical information. Rose trees in particular offer flexibility by allowing nodes to have any number of branches.

Rose Trees

Rose trees have a variable and unbounded number of branches per node.

Each node T holds a list of its children. This makes it incredibly expressive, allowing for structures where some nodes have no children while others have many.

tree.ml 
type tree = T of tree list

let t1 = T []
(* A single leaf / atomic tree *)

let t2 = T [t1; t1; t1]
(* A node with three leaf children *)

let t3 = T [T [t2]; t1; t2]
(* A deeper nested tree *)
Step 1. let t1 = T [] creates a single atomic tree (a leaf with no children).
Step 2. let t2 = T [t1; t1; t1] creates a new root node containing a list of three t1 children.
Step 3. let t3 = T [T [t2]; t1; t2] embeds the previous trees into an even deeper structure, demonstrating unbounded arity.

Terminology

Understanding tree terminology is essential for navigating and manipulating these structures:

  • Atomic tree: T [] (no children)
  • Compound tree: any tree with at least one child
  • Root: the top node
  • Inner nodes: non leaf nodes
  • Arity of a tree t = T [t0; ...; t_{n-1}]: the number n of its children
  • Successor trees: the children t0, ..., t_{n-1}
properties.ml 
let arity (T ts) = List.length ts

let succtree (T ts) k = List.nth ts k

Computing the Number of Nodes

The node count is computed recursively from successor trees. Each leaf contributes 1. Each inner node contributes 1 plus the sum of its children's node counts.

The approach combines three ideas:

  1. Recurse on successor trees.
  2. Use map to apply the function to each child.
  3. Use fold_left to aggregate the results.
Pattern

This function maps size over all children to get a list of counts, then folds with addition starting from 1 for the current node itself.

size.ml 
let rec size (T ts) =
  List.fold_left (+) 1 (List.map size ts)
size (T [T []; T []])

fold_left (+) 1 [size (T []); size (T [])]
fold_left (+) 1 [1; 1]

Step 2. The root calls List.map size on its children, propagating downwards.
Step 3. The leaves evaluate their base case (1) and return these values to the map function, yielding [1; 1].
Step 4. The root node receives [1; 1] and uses fold_left (+) 1 to sum the list plus its own 1, returning 3.

Linearizations

A linearization turns a tree into a flat sequence, useful whenever you need to print, serialize, or compare trees as simple lists. The two natural strategies differ only in when a node contributes to the output relative to its children.

The key to understanding why the two strategies produce different lists is the standard tour: a traversal that visits every node twice, once descending (first visit) and once returning (last visit), with successor trees explored left to right. pre emits a node's arity on the first visit; post emits it on the last visit. This is the causal chain the interactive demo below makes concrete.

pre records a node's arity before recursing into its children (left to right); post records it after. Both share the same recursive shape as size; only the position of the node's own contribution changes.

Pattern

Same tree, same traversal order, two different output sequences, purely because of where each node's value is placed relative to List.concat (List.map ... ts).

linearize.ml 
let rec pre (T ts) =
  List.length ts :: List.concat (List.map pre ts)

let rec post (T ts) =
  List.concat (List.map post ts) @ [List.length ts]

Labeled Trees and Projections

A 'a ltree attaches a label of type 'a to every node. Projections collect those labels into a list (prep in pre-order, pop in post-order) using exactly the same recursive shape as pre and post, just collecting labels instead of counting children.

Read prep as "this node's label, then its children's labels, left to right"; pop as "the children's labels first, then this node's label last". The traversal order is identical to pre/post; only what gets collected (a label vs. an arity) differs.

Pattern

prep t = [x] @ List.concat (List.map prep ts) mirrors pre's List.length ts :: ...; pop mirrors post in the same way.

project.ml 
type 'a ltree = L of 'a * 'a ltree list

let rec prep (L (x, ts)) =
  [x] @ List.concat (List.map prep ts)

let rec pop (L (x, ts)) =
  List.concat (List.map pop ts) @ [x]

Balanced Trees

A tree is balanced when every node's successor trees all have the same depth. Checking this calls for something size never needed: a way to fail when two computed depths disagree, which is exactly what exceptions are for.

check n m returns the common value when n = m, and otherwise raises Unbalanced. depthb folds check over the depths of all successor trees, starting from the depth of the first one, so any mismatch propagates the exception straight out of the fold. balanced simply trys depthb and turns the exception into false.

Pattern

Exceptions let depthb stay a clean total-looking recursion: the "all depths agree" invariant is enforced by check, and balanced is the one place that decides what a violation means (here, simply false).

balanced.ml 
exception Unbalanced

let check n m = if n = m then n else raise Unbalanced

let rec depthb (T ts) = match ts with
  | [] -> 0
  | t :: tr -> 1 + List.fold_left check (depthb t) (List.map depthb tr)

let balanced t =
  try (let _ = depthb t in true)
  with Unbalanced -> false
